Audit the Razor views in Template.Web/Views against the entity classes in
Template.Data/Entities and enums in Template.Common/Enums. Do not edit any
files yet — produce a gap report first.

For each of these views, cross-check every form field, table column, and
displayed value against the entity(ies) it should represent:

- Views/Idea/Submit.cshtml          → InnovationIdea (+ IdeaAttachment)
- Views/Idea/MyIdeas.cshtml         → InnovationIdea
- Views/Idea/Details.cshtml         → InnovationIdea, Comment, IdeaAttachment, IdeaTimeline
- Views/Idea/Review.cshtml          → InnovationIdea, IdeaTimeline, StageHistory, Comment
- Views/Idea/AllIdeas.cshtml        → InnovationIdea
- Views/Category/Index.cshtml       → Category
- Views/Resource/Index.cshtml       → Resource (uses ResourceCategory enum)
- Views/Report/Index.cshtml         → Report (uses ReportType, ReportFormat, ScheduleFrequency enums)
- Views/Notification/Index.cshtml   → Notification (uses NotificationType enum)
- Views/Account/*.cshtml            → ApplicationUser, Role
- Views/AuditLog/Index.cshtml       → AuditLog (uses AuditEventType, AuditStatus enums)
- Views/Role/*.cshtml               → Role
- Shared/Components/*Dashboard/Default.cshtml → InnovationIdea, IdeaTimeline (summary/aggregate data)

For each view, report:
1. **Fields in the entity with no corresponding UI element** in the view
   (e.g. if InnovationIdea.ProblemStatement has no textarea in Submit.cshtml)
2. **Fields in the view with no matching entity property** (dead/placeholder
   inputs, or fields referencing an entity that doesn't exist yet)
3. **Enum-backed fields not rendered as dropdowns/selects** bound to the
   correct enum (e.g. Resource.Category should be a <select> populated from
   ResourceCategory, not a free-text input)
4. **Type mismatches** (e.g. a date field bound to a string, a numeric ID
   field exposed as free text instead of a hidden field/select)
5. **Missing validation attributes on file that should mirror the entity's
   `required` modifiers** (e.g. required string properties should have
   corresponding [Required] / asp-validation-for in the view)

Known gaps to flag but NOT fix yet, since they need a design decision first:
- InnovationIdea.CurrentStage / CurrentStatus are typed as string, not the
  IdeaStage/IdeaStatus enums — note anywhere a view is rendering these as
  free text instead of a fixed set of options, since that will need to
  change once the stage/status representation is unified.
- InnovationIdea has no BusinessUnit, Station, IdeaTeamMember, or
  StrategicObjective relations yet — if any view already has form fields
  for these (e.g. Submit.cshtml likely does, since the original submission
  form had Business Unit / Station / Strategic Alignment fields), flag
  that the view is currently ahead of the entity model, not the other way
  around.

Output as a markdown table per view:
| Field/Element in View | Corresponding Entity Property | Status (OK / Missing in Entity / Missing in View / Type Mismatch / Needs Enum Dropdown) | Note |
