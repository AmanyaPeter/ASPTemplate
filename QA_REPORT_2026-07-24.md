## Defects

### QA-DEF-001 - Category repository does not implement its interface

- Severity: **P0**
- File: `Template.Core/Repository/Category/CategoryRepository.cs`
- Reproduction: run `dotnet build Template.sln --no-restore`.
- Actual:
  - `CategoryRepository` does not implement `IsReferencedAsync(int)`.
  - `SoftDeleteAsync(int)` returns `Task<bool>` but the interface requires `Task<(bool Success, bool Referenced)>`.
- Expected: implementation and interface signatures match.
- Additional impact: `CategoryController.Delete` currently treats the return value as `bool`; if the tuple interface is retained, that controller action must also be updated.

### QA-DEF-002 - Category filter controls are not submitted correctly

- Severity: **P2**
- File: `Template.Web/Views/Category/Index.cshtml`
- Actual: visible search/status controls are outside `filterForm`; the form contains separate hidden `asp-for` controls. Changing visible values does not automatically update hidden values.
- Expected: visible controls belong to the GET form or JavaScript synchronizes values before submission.

### QA-DEF-003 - Category page duplicates the shared navigation shell

- Severity: **P2**
- File: `Template.Web/Views/Category/Index.cshtml`
- Actual: page renders its own sidebar and header while the shared layout also supplies them.
- Expected: feature view contains content only and uses `_Layout.cshtml`.

### QA-DEF-004 - Resource files are stored/served under web root

- Severity: **P1**
- File: `Template.Web/Controllers/ResourceController.cs`
- Actual: resource path is rooted under `environment.WebRootPath/uploads/resources`.
- Expected: uploaded documents are outside `wwwroot` and returned only through an authorized, path-contained controller action.

### QA-DEF-005 - Login POST lacks anti-forgery protection

- Severity: **P1**
- File: `Template.Web/Controllers/AccountController.cs`
- Actual: POST Login has `[HttpPost]` but no `[ValidateAntiForgeryToken]`.
- Expected: login form and action use anti-forgery validation.

### QA-DEF-006 - Login error may disclose authentication detail

- Severity: **P1**
- File: `Template.Web/Controllers/AccountController.cs`
- Actual: response displays `Failed login. {result.Status}`.
- Expected: generic invalid-credentials message that does not reveal whether username, password, lock, or account existence caused failure, except where approved after authentication.

### QA-DEF-007 - Offline/on-premises pages depend on public CDNs

- Severity: **P2**
- Files: shared layout, Category view, Report view.
- Actual: Select2, DataTables, jQuery, Lucide, and Chart.js are referenced from public CDNs.
- Expected: active production assets are served locally so the application functions without internet access.

### QA-DEF-008 - Excel export is not a real Excel workbook

- Severity: **P2**
- File: `Template.Web/Controllers/ReportController.cs`
- Actual: CSV text is returned with `.xls` extension and Excel MIME type.
- Expected: generate a valid `.xlsx` workbook, or label the output honestly as CSV.

### QA-DEF-009 - Report export ignores the selected report filters

- Severity: **P2**
- File: `Template.Web/Controllers/ReportController.cs`
- Actual: `Export` always calls `Query(new ReportFilterViewModel())`.
- Expected: export receives and applies the same validated filters as the displayed report.

### QA-DEF-010 - Report query loads the complete filtered dataset into memory

- Severity: **P2**
- File: `Template.Web/Controllers/ReportController.cs`
- Actual: `BuildReport` calls `ToListAsync()` before pagination and aggregation.
- Expected: database-side count, aggregation, and pagination for scalable datasets.

### QA-DEF-011 - No automated test projects detected

- Severity: **P2**
- Actual: no project matching `*Tests.csproj` or `*Test.csproj` exists.
- Expected: unit/integration/MVC tests for ownership, workflow, category behavior, notifications, and authorization.
